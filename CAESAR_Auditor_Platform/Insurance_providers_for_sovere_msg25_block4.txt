4. INCIDENT SEVERITY CLASSIFICATION

CRITICAL (P1):
• Confirmed data breach with PII exposure
• Ransomware affecting production systems
• Complete service outage (JUDAS platform down)
• Compromise of HSM or cryptographic keys
Response Time: Immediate (15 minutes)

HIGH (P2):
• Suspected unauthorized access
• Malware detection on production systems
• Partial service degradation
• Loss of device with sensitive data
Response Time: 1 hour

MEDIUM (P3):
• Failed intrusion attempt (blocked by controls)
• Phishing attempt reported
• Minor policy violation
Response Time: 4 hours

LOW (P4):
• Security awareness issue
• Non-sensitive information disclosure
Response Time: Next business day

5. INCIDENT RESPONSE PHASES

5.1 DETECTION & ANALYSIS (First 2 hours)
✓ Incident reported via security@cdlslogistics.com or [PHONE]
✓ Incident Commander notified immediately
✓ Initial triage and severity classification
✓ Activate incident response team
✓ Preserve evidence (logs, system snapshots)
✓ Document timeline in incident log

Initial Assessment Questions:
• What systems are affected?
• What data is potentially compromised?
• How was the incident detected?
• Is the threat still active?
• Are customers impacted?

5.2 CONTAINMENT (Hours 2-6)
✓ Isolate affected systems (disconnect from network if necessary)
✓ Reset compromised credentials
✓ Block malicious IPs/domains at firewall
✓ Preserve forensic evidence before containment actions
✓ Implement compensating controls
✓ Monitor for lateral movement

Short-Term Containment (Immediate):
• Disable compromised accounts
• Isolate infected systems
• Block attack vectors

Long-Term Containment (While investigating):
• Apply emergency patches
• Deploy additional monitoring
• Segment network if needed

5.3 ERADICATION (Hours 6-24)
✓ Remove malware, backdoors, unauthorized access
✓ Patch vulnerabilities exploited in attack
✓ Strengthen affected security controls
✓ Validate that threat actor is completely removed
✓ Scan all systems for indicators of compromise (IOCs)

5.4 RECOVERY (Hours 24-72)
✓ Restore systems from clean backups (if needed)
✓ Verify system integrity before bringing online
✓ Enhanced monitoring for 30 days post-incident
✓ Gradual restoration of services (not all at once)
✓ Customer communication (if service was impacted)

5.5 POST-INCIDENT (Within 7 days)
✓ Incident post-mortem meeting
✓ Document lessons learned
✓ Update incident response procedures
✓ Implement preventive controls
✓ Security awareness communication to team
✓ Final incident report to stakeholders

8. SPECIFIC INCIDENT SCENARIOS

8.1 Ransomware
✓ DO NOT pay ransom (policy)
✓ Isolate infected systems immediately
✓ Identify patient zero
✓ Restore from backups (verified clean)
✓ Report to FBI (Internet Crime Complaint Center)

8.2 Phishing / Credential Compromise
✓ Reset compromised user password immediately
✓ Review account activity logs for unauthorized access
✓ Check for forwarding rules, API keys created
✓ Force logout all sessions
✓ Security awareness reminder to all staff

8.3 Data Breach (PII Exposure)
✓ Determine scope: how many records, what data elements
✓ Assess legal notification requirements (CCPA, etc.)
✓ Notify affected individuals (if required by law)
✓ Offer credit monitoring (if SSN/financial data exposed)
✓ Report to regulators within required timeframe
✓ Notify cyber insurance immediately

8.4 Insider Threat
✓ Immediately disable access
✓ Preserve evidence (logs, emails, files accessed)
✓ Legal counsel consultation
✓ Law enforcement (if criminal activity)
✓ Review access logs for data exfiltration

8.5 DDoS Attack on JUDAS Platform
✓ Activate DDoS mitigation (Cloudflare, AWS Shield)
✓ Identify attack vectors and block source IPs
✓ Scale infrastructure to absorb load (if possible)
✓ Notify customers of potential service degradation
✓ Report to ISP / law enforcement
